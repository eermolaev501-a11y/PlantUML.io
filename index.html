Логическая модель данных (ERD)

ER-диаграмма

Описание сущностей

Сущность Назначение Ключевые ограничения
ДДМ Документ движения материалов Отправляющий объект ≠ принимающий объект
Владелец запаса Справочник владельцев (ответственное хранение) Обязателен только при StockType = CONSIGNMENT
Объект обслуживания Справочник объектов (склады, цеха) Два FK в ДДМ: отправляющий и принимающий
Позиция ТМЦ Строки документа с ТМЦ Минимум 1 позиция на ДДМ
Комментарий Текстовое примечание к ДДМ Не более 1 на ДДМ

Связи

Связь Кардинальность Тип Поведение при удалении
ДДМ → Владелец запаса 0..1 — 0..* Неидентифицирующая SET NULL
ДДМ → Объект обслуживания (отправл.) 1 — 0..* Неидентифицирующая RESTRICT
ДДМ → Объект обслуживания (приним.) 1 — 0..* Неидентифицирующая RESTRICT
ДДМ → Позиция ТМЦ 1 — 0..* Идентифицирующая CASCADE
ДДМ → Комментарий 1 — 0..1 Неидентифицирующая CASCADE

Нормализация

Модель в 3NF:

  • Все атрибуты атомарны (нет повторяющихся групп).
  • Позиции ТМЦ вынесены в отдельную сущность (нет массивов в ДДМ).
  • Владелец запаса и объекты обслуживания — отдельные справочники, нет транзитивных зависимостей.

Физическая модель данных (DDL)

ER-диаграмма (физический уровень)

DDL-скрипт (PostgreSQL 14+) 

-- ===== Типы (enum) =====
CREATE TYPE stock_type_enum AS ENUM ('OWN', 'CONSIGNMENT');
CREATE TYPE ddm_status_enum AS ENUM ('DRAFT', 'SAVED', 'CANCELLED');

-- ===== Таблицы =====

CREATE TABLE stock_owner (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(255) NOT NULL,
    inn         VARCHAR(12) CHECK (inn ~ '^[0-9]{10,12}$')
);

CREATE TABLE service_object (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(255) NOT NULL,
    code        VARCHAR(50) NOT NULL,
    type        VARCHAR(50) NOT NULL
);

CREATE TABLE ddm (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    number              VARCHAR(50) NOT NULL,
    operation_type      VARCHAR(20) NOT NULL DEFAULT 'Отгрузка',
    sub_operation_type  VARCHAR(20) NOT NULL DEFAULT 'В путь',
    stock_type          stock_type_enum NOT NULL,
    status              ddm_status_enum NOT NULL DEFAULT 'DRAFT',
    created_at          TIMESTAMP NOT NULL DEFAULT now(),
    created_by          VARCHAR(100) NOT NULL,
    comment             TEXT,
    stock_owner_id      UUID REFERENCES stock_owner(id) ON DELETE SET NULL,
    sending_object_id   UUID NOT NULL REFERENCES service_object(id) ON DELETE RESTRICT,
    receiving_object_id UUID NOT NULL REFERENCES service_object(id) ON DELETE RESTRICT,
    CHECK (sending_object_id <> receiving_object_id),
    CHECK (stock_type = 'CONSIGNMENT' AND stock_owner_id IS NOT NULL
           OR stock_type = 'OWN')
);

CREATE TABLE ddm_position (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ddm_id      UUID NOT NULL REFERENCES ddm(id) ON DELETE CASCADE,
    tmc_id      UUID NOT NULL,
    tmc_name    VARCHAR(500) NOT NULL,
    quantity    NUMERIC(18,3) NOT NULL CHECK (quantity > 0),
    unit        VARCHAR(20) NOT NULL
);

CREATE TABLE ddm_comment (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ddm_id      UUID NOT NULL REFERENCES ddm(id) ON DELETE CASCADE,
    text        TEXT NOT NULL,
    author      VARCHAR(100) NOT NULL,
    created_at  TIMESTAMP NOT NULL DEFAULT now()
);

-- ===== Индексы =====
CREATE INDEX idx_ddm_status        ON ddm(status);
CREATE INDEX idx_ddm_stock_type    ON ddm(stock_type);
CREATE INDEX idx_ddm_created_at    ON ddm(created_at DESC);
CREATE INDEX idx_ddm_position_ddm  ON ddm_position(ddm_id);
CREATE UNIQUE INDEX uq_ddm_comment_ddm ON ddm_comment(ddm_id);

-- ===== Триггер: минимум 1 позиция =====
CREATE OR REPLACE FUNCTION check_ddm_has_positions()
RETURNS TRIGGER AS $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM ddm_position WHERE ddm_id = NEW.id) THEN
        RAISE EXCEPTION 'ДДМ % должен содержать минимум одну позицию', NEW.id;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_ddm_check_positions
AFTER INSERT OR UPDATE ON ddm
FOR EACH ROW EXECUTE FUNCTION check_ddm_has_positions();

Таблица решений

Решение Обоснование
UUID вместо BIGSERIAL ДДМ создаётся в распределённой системе, UUID исключает коллизии
CHECK sending_object_id <> receiving_object_id Бизнес-правило: нельзя отгрузить самому себе
CHECK на stock_type + stock_owner_id При «Ответственное хранение» владелец обязателен, при «Собственный» — не нужен
Триггер на минимум 1 позицию ДДМ без позиций не имеет смысла
SET NULL для stock_owner_id Если владельца удалили — ДДМ сохраняется, но теряет ссылку
RESTRICT для service_object Нельзя удалить объект, на который ссылаются ДДМ
CASCADE для ddm_position и ddm_comment Позиции и комментарии не существуют без ДДМ

Особенности архитектуры

  • Прямые вызовы из браузера к MS MasterData — SPA обращается к REST Gateway MasterData напрямую для получения справочников (владельцы запаса, объекты обслуживания). Backend АС Учет задействуется только для поиска позиций ТМЦ и создания ДДМ.
  • Два backend-сервиса — DDM Service (создание ДДМ) и Stock Service (поиск ТМЦ) — разделены по доменной ответственности.
  • OpenShift IFT-GEN1 — обе системы развёрнуты в одном OpenShift-кластере, что обеспечивает низкую задержку межсервисных вызовов.
